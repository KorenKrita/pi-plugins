Fixed Input Implementation Notes

Final-answer auto-jump

Provenance: user-decided

  • After a turn settles, automatic navigation targets the dynamically rendered text child of the final assistant component, not message start, thinking, or tool calls.
  • The jump is considered only when that final text range exceeds the visible transcript viewport, and the range is recalculated after resize/reflow.
  • Any user scroll intent during the turn cancels automatic navigation for that turn, even when the viewport cannot move or later returns to the bottom.
  • When actual user scrolling leaves the bottom, the compositor preserves the chosen viewport start across transcript growth and temporary shrinkage; losing scroll range must not silently resume bottom-following.
  • Submitting a new prompt programmatically returns the transcript to the bottom before tracking the new turn; this system navigation does not count as user scroll intent.

Compositor hardening

Provenance: agent-resolved

  • User viewport preservation uses a printable-content signature, neighboring-line context, and an independent logical fallback; temporary clamping must not overwrite the durable anchor, and repeated lines must be disambiguated by context.
  • Only visible capturing overlays suspend compositor input and rendering behavior.
  • Unhandled SGR mouse packets and right-clicks without a selection pass through to Pi. Copied selections remove complete or unterminated terminal control strings and disallowed C0/C1 controls.
  • Selection completion performs one clipboard write; asynchronous clipboard failures are caught and surfaced through Pi UI.
  • Terminal/TUI monkey patches, hidden renderers, and the editor factory are restored only when the installed wrapper is still owned by this extension.
  • The original own rows descriptor is distinguished from an inherited descriptor; data descriptors are read directly to avoid recursive access through the installed getter.
  • Kitty keyboard mode uses push/pop semantics; an already-active modifyOtherKeys mode is explicitly re-enabled after leaving the alternate screen.
  • The private five-slot Pi layout around the editor is validated before any component is hidden; a real Pi 0.80.6 loader lifecycle smoke test guards this seam.
  • A one-row terminal remains one row and bypasses split painting rather than drawing into a fabricated second row.
